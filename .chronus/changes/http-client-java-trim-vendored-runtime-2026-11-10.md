Reduce the shipped generator size by keeping only the vendored Eclipse formatter code reachable from the generator's formatter entry point. Constant parameters, fields, named constants, and constant returns are inlined; unread fields, unused parameters, empty methods, unobserved AST bookkeeping, and the compiler's binding layer are removed; single-implementation and marker types are folded; and vendored Javadoc and comments no longer reference removed or upstream-only code. The formatter always parses source with the Java 8 language rules plus module declarations, so support for newer syntax, such as `var`, private interface methods, switch rules and expressions, records, text blocks, pattern matching, module imports, Javadoc snippets, and Markdown documentation comments, is removed. Identifier characters follow the JDK that runs the generator instead of shipped Unicode tables. The generator's formatter profile is built into the formatter instead of being read at run time, and diagnostics no longer build message text. Generated Java formatting is unchanged on Java 17; newer JDKs also treat letters from later Unicode versions as identifier characters. The formatter returns the formatted source directly, so the vendored JFace document and text-edit model and the Equinox runtime helpers are no longer shipped, and the vendored sources are grouped into five packages instead of following Eclipse's public and internal API packages. The emitter jar also no longer packages Maven, multi-release, or GraalVM native-image metadata from bundled libraries, or the notices and metadata of Eclipse bundles whose code is not shipped.
