# Pre-emission implementation guide

Apply this guide with the [task handoff index](./pre-emission-task-handoffs.md),
the individual handoff and its linked authoritative issue comment.

## Authority and current baseline

Planning is centralized on fork branch **feature/pre-emission-field-types**,
starting at 674e6ca75851acab5e4289e4034878664b102264, after Tasks01-03 merged.
These documents authorize no new public/default rollout or source changes by
the documentation commit itself. Task04 and later capabilities described here
are plans, not already implemented interfaces.

The revised task comments and
[Task19](https://github.com/microsoft/typespec/issues/12454#issuecomment-6543557177)
supersede the old issue-body compiler-owner/hybrid design. Task03's bounded
completion contract is not permission to narrow another task's accepted cases.

## One architecture, not one proof framework per task

- Prepare occurrence-owned decisions before one standard writer traversal, from
  finalized provider/IR contracts and already loaded source/reference symbols.
  The writer consumes choices; it does not bind or parse generated output.
- Reuse canonical identities, shared catalogs, source observations, input guards,
  actual-use receipts and captured qualified alternatives. Preserve sticky
  observed invalidation and independent safe decisions. No callback replay,
  forced lazy carriers, new compiler host or parallel preparation lifecycle.
- Keep lexical/shape facts, selected calls, observation absence, source policy,
  grammar and editing permission distinct. Intended signatures, advertised
  expression types or a caller-provided safety boolean are not authority.
- Share facts at their real scope; keep permissions per occurrence and child
  position. No type/producer-key permission cache or removal of mutable
  observation points merely because frozen bookkeeping was simplified.
- A missing fact remains unknown. Retain the affected form, but do not count
  retention as completion of an accepted shortening positive.

The existing core has narrow adopted profiles. A later consumer may need a
bounded shared prerequisite; it must identify that case and owner instead of
finishing every possible source-observation family first.

## Inventory and first checkpoint before breadth

For each task, map the original accepted fixtures to concrete writer/IR slots,
required scope/target/construction/source facts and test oracles. Preserve whole
mixed fixtures, real local delegates, instance helpers, omitted caller-expression
arguments and source-part relationships. Do not substitute easier fixtures or
different source authority to bypass the reported case.

Use the frozen [Structural test collection](https://github.com/live1206/typespec/tree/7ac8b2640bcfa42f96e1095fb208de83b911fe71/packages/http-client-csharp/generator/Microsoft.TypeSpec.Generator/test)
and [follow-up ledger](./pre-emission-task03-follow-up-ledger.md). Its relevant
cases are obligations, not a requirement for each task to implement all 44 files.
Task04's namespace-call inventory includes cases 0-11, not just 0-8.

Before significant machinery, identify:

1. The accepted anchor, actual consumer and desired raw change.
2. The smallest missing fact, using existing interfaces where possible.
3. Eligible/enabled occurrences or another explicitly bounded benefit estimate.
4. Retained controls, affected dependencies and the validation plan.

First produce one real prepared/raw-writer/pipeline slice, then review its
incremental benefit and complexity before adding another family. Do not create a
general profiling framework, full SDK campaign or proof-count target.

## Contracts that need special care

- A type-only lookup does not prove a value-sensitive static receiver lookup.
- Task08 simplifies direct optional-parameter defaults from `default(T)` to
  `default`. It does not remove default clauses, parameters or call arguments.
- Task10 owns its recorded retained SDK cast, not arbitrary cast removal.
- Conditional tasks concern the supported directive/configuration profile; they
  do not authorize a general preprocessor solver or blanket inactive-source edit.
- Task13 owns the exact accepted
  `StructuralConditionalStaticReceiverReducedExtensionReceiverCapture(false/true)`
  pair with original expectations and controls. General conditional property
  expansion remains excluded.
- Documentation decisions need actual whole-type/producer ownership. Ordinary
  type plans must not accidentally activate attribute or documentation families.
- Original import witnesses and surviving prepared uses are different facts.
  Do not make a reduction justify its own import through a circular witness.
- Reusing an existing residual migration path is permitted until its family is
  migrated. Final Task19 replacement cannot call general `Simplifier.ReduceAsync`,
  including opaque/custom cases, or introduce a per-family post-write substitute.

## Scope stops, not hidden redefinitions

Pause an expansion before building a general binder/inference/CFG/parser,
arbitrary callback/factory purity engine, new host, broad language-emission
framework or another lifecycle. Present the concrete original case, benefit and
bounded alternatives. Continue other independent authorized work.

Raw-only or unrepresented accepted syntax requires a bounded role/emission
decision, not automatic development of every language feature. It also cannot
be silently labeled unsupported to finish the task. Reassignment or narrower
completion requires explicit agreement and a retained owner/anchor ledger.

Do not fix unrelated emitter behavior or change baseline diagnostics to make a
fixture healthy. Do not expand conditional properties, default expressions,
foreign-model casts, generic/nested import activation or policy profiles merely
because adjacent code can be reused.

## Validation and completion

Reproduce the exact original failure before production edits. Assert prepared
decisions and raw spelling/form before legacy processing; then parse/compile in
tests and compare exact symbols/constructions/conversions/constants, diagnostics,
emit/runtime, observed source and reflection/XML where relevant.

Keep negative and forced-unsafe-edit controls. Preserve original expectations;
do not delete, mute, substitute or weaken a regression to obtain green tests.
Before declaring a proof/fix redundant, compare base and candidate behavior.

Iterate with focused tests. At stable scope run required broader generator/client
and affected integration checks plus independent review; repeat checks invalidated
by changes, not unchanged campaigns. Record revision, executed cases and CI gaps.
No SDK regeneration, public activation or benchmark is implicitly authorized.

A first checkpoint is not full task completion. Full completion requires its
accepted positives and retention controls, raw/pipeline evidence and relevant
composition, unless an explicit scope agreement says otherwise. Do not claim
overall issue completion, SDK adoption or performance from fixture counts.

Readable final SDK spelling is a requirement: `global::` is not an accepted
permanent escape hatch for difficult reductions. Preserve source-observation
semantics; escalate any concrete conflict in final output policy instead of
silently rewriting captured text or broadening a source-equivalence engine.
